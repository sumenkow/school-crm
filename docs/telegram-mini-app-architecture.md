## YouEurope / Smart Academy CRM — Phase 10

## 1. Резюме и Архитектурный Закон

Настоящий документ разработан объединенной группой **Agent 1 (Telegram Integration Architect)** и **Agent 2 (CRM Domain Analyst)** в рамках **Phase A** (Read-Only этап). 

### Ключевой закон этапа:
1. **Zero New Entities**: Никаких новых таблиц базы данных (`TelegramBooking`, `ParentBooking`, `BookingSlot` и т.д.). Запись родителя создает или обновляет исключительно существующие сущности: `Lesson` (с добавлением ученика в `lesson.students` или созданием индивидуального `Lesson`) и существующий `Student`.
2. **Сохранение существующего чата**: Существующий канал общения родителей и администраторов (`Родитель ↔ Telegram Bot ↔ Webhook ↔ CRM ChatBox ↔ Администратор`) **остается на 100% неприкосновенным**. Mini App подключается исключительно как дополнительная точка входа (кнопка `web_app`), не перехватывая и не изменяя обработку входящих текстовых сообщений.
3. **Безопасность и IDOR-защита**: Сервер никогда не доверяет `parentId`, `studentId` или `capacity` из фронтенда. Идентификация родителя происходит по подтвержденному `telegramChatId` / Telegram WebApp initData, а запись разрешена только для детей, привязанных к этому родителю.
4. **Инвариант нулевого списания при бронировании**: Бронирование занятия родителем строго **не списывает средства с баланса или абонемента**. Списание происходит исключительно по существующему бизнес-правилу при фактическом посещении занятия (`conducted` / отметка в `attendance`).

## 2. Фиксация существующего Telegram Workflow (Section 42 Compliance)

В соответствии с требованием п. 42 технического задания зафиксирован точный поток данных текущей интеграции Telegram в кодовой базе:

```
[Родитель в Telegram]
        │
        ▼ (Текстовое сообщение /start или произвольный вопрос)
[Telegram Bot API: https://api.telegram.org]
        │
        ▼ POST webhook (Allowed updates: 'message', 'callback_query')
[CRM Webhook Route: src/app/api/telegram/webhook/route.ts]
        │
        ├─► 1. Если текст startsWith('/start'):
        │      ├─ Анализ deeplink payload ('st_ID', 'lead_ID', 'par_ID')
        │      ├─ Обновление поля `telegram` в таблицах `students`/`leads`/`parents`
        │      ├─ Запись события в таблицу `interactions` (канал 'telegram', тип 'status_change')
        │      └─ Ответное приветствие через sendTelegramDirectMessage()
        │
        ├─► 2. Если обычное сообщение:
        │      ├─ Трёхуровневая идентификация контакта:
        │      │   - Tier 1: Точный поиск по числовому chatId в `students`, `parents`, `leads`
        │      │   - Tier 2: Поиск по username / недавней истории исходящих сообщений в `interactions`
        │      │   - Tier 3: Авто-привязка найденного контакта к chatId
        │      ├─ Сохранение входящего сообщения в таблицу `interactions`
        │      │   (content: «💬 Входящее в Telegram: ...», channel: 'telegram', type: 'follow_up')
        │      └─ Пересылка уведомления администратору в Telegram (если задан TELEGRAM_ADMIN_CHAT_ID)
        │
[CRM Desktop Interface: src/components/telegram/TelegramChatBox.tsx]
        │
        ├─ Периодический опрос / подписка через `/api/telegram/messages?type=...&id=...`
        ├─ Отображение сообщений администратору (пузыри, статусы, таймлайны)
        │
[Ответ администратора из CRM]
        │
        ▼ POST /api/telegram/send
[sendTelegramDirectMessage() в telegramClient.ts]
        │
        ├─ POST https://api.telegram.org/bot{TOKEN}/sendMessage
        └─ Запись исходящей реплики в `interactions` (content: «✈️ Сообщение в Telegram: ...»)
```

### Гарантия неизменности:
- Маршрут `POST /api/telegram/webhook` сохраняет всю ветку обработки обычных сообщений.
- Добавляется лишь поддержка команд меню бота (`📅 Записаться на занятие`, `/book`) и отправка WebApp инлайн-кнопки для запуска Mini App.
- Исходящие сообщения администратора через `POST /api/telegram/send` продолжают работать без модификаций существующей структуры сообщений.

### Экран 1: Главное меню Mini App (`/mini-app`)
- **Заголовок**: «You Europe · мини-приложение».
- **Приветствие**: Персонализированное приветствие родителя (например, *«Здравствуйте, Ольга! Выберите, что хотите сделать»*) с аватаром.
- **Быстрые карточки**:
  1. `📅 Записаться на занятие` (Групповое, индивидуальное или пробное) → переход на Экран 2.
  2. `📚 Мои занятия` (Расписание и история) → список текущих занятий детей.
  3. `👨‍👩‍👧 Мои дети` (Список привязанных учеников) → карточки детей с возрастом.

## 5. Модель безопасности, авторизация и защита от Race Conditions

1. **Верификация авторизации Telegram WebApp**:
   - Браузер передает заголовок `x-telegram-init-data` или параметр `initData` / `chatId`.
   - Сервер валидирует хэш подписи с использованием `TELEGRAM_BOT_TOKEN`.
   - По полученному `telegram_id` сервер находит соответствующего `Parent` в базе данных.
2. **Проверка владения учеником (Student Ownership Guard)**:
   - При бронировании бэкенд проверяет:
     `const allowedStudents = getStudentsForParent(parentId);`
     `if (!allowedStudents.some(s => s.id === requestedStudentId)) throw new ForbiddenError();`
   - Исключена возможность записи чужого ребенка.
3. **Атомарная защита от Race Conditions при записи на последнее место**:
   - При одновременном нажатии кнопки «Записаться» двумя родителями, проверка остатка свободных мест (`capacity - currentStudentsCount > 0`) и добавление ученика выполняются в единой синхронной/атомарной транзакции в хранилище.
   - Второй запрос возвращает понятную ошибку: *«К сожалению, последнее свободное место только что заняли. Пожалуйста, выберите другое время»*.
4. **Защита от двойного бронирования (Double Booking Prevention)**:
   - Проверка: ученик уже записан на данный урок → повторная запись блокируется с информационным сообщением.
   - Проверка пересечения расписания ученика через `collisionHelper.hasStudentCollision(...)`.
